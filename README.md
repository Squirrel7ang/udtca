# udtca

This repository is a workspace for distributed-training communication
experiments. It combines two submodules, `bitscom` and `polar-sgd`, with local
experiment scripts for low-bit communication, Polar SGD, pipeline/data/tensor
parallel training, YOLOv8 partial-gradient synchronization, collective
benchmarks, and plotting/analysis artifacts.

## Experiment Entry Points

### Quantization and low-bit communication

The main quantization workspace is [`experiments/quantization/`](experiments/quantization/).
It contains scripts for:

- dense all-reduce baselines (`none`)
- int8 quantization (`quant8`)
- top-k sparsification (`topk`)
- PowerSGD (`powersgd`)
- bitscom low-bit communication (`bitscom`)
- PolarParallel + bitscom Llama7B DP/PP experiments
- result summarization and plotting

Start with [experiments/quantization/README.md](experiments/quantization/README.md)
for run commands and method notes.

### Qwen14B DP/PP/TP

The Qwen14B workspace is [`experiments/qwen14b/`](experiments/qwen14b/).
It targets a two-node, 32-GPU topology:

- DP = 2 across nodes
- PP = 8
- TP = 2
- 1F1B pipeline schedule
- optional POLAR + bitscom path
- dense DP baseline path

See [experiments/qwen14b/README.md](experiments/qwen14b/README.md) for the
node-0/node-1 launch commands.

### YOLOv8 DDP partial-gradient sync

Script: [`experiments/yolov8/run_yolov8_ddp_partial_sync.py`](experiments/yolov8/run_yolov8_ddp_partial_sync.py)

Example single-node, 4-GPU run:

```bash
torchrun --nproc_per_node=4 experiments/yolov8/run_yolov8_ddp_partial_sync.py \
  --model yolov8n-cls.pt \
  --data /path/to/classification_dataset \
  --sync-interval 4 \
  --steps 100
```

Notes:

- `--sync-interval N` synchronizes roughly `1/N` of gradient buckets per step
  and performs an optimizer update every `N` steps.
- `--bucket-numel` can be tuned to align bucket counts with `--sync-interval`.
- If `--data` is omitted, synthetic classification data is used.

### Collective communication

The [`experiments/collectives/`](experiments/collectives/) directory contains
hierarchical all-reduce tests and Corex launch scripts. It is useful for
isolating collective behavior outside full model training.

### Plotting and post-processing

Plotting and summary helpers are spread across the experiment directories:

- [`plot_tb_scalars.py`](plot_tb_scalars.py) reads TensorBoard scalar exports
  and produces comparison artifacts.
- [`experiments/quantization/plot_step_csv_curves.py`](experiments/quantization/plot_step_csv_curves.py)
  plots step-level CSV curves.
- [`experiments/quantization/plot_bandwidth_throughput.py`](experiments/quantization/plot_bandwidth_throughput.py)
  estimates bandwidth/throughput tradeoffs.
- [`experiments/quantization/plot_batch_size_sweep.py`](experiments/quantization/plot_batch_size_sweep.py)
  plots batch-size sweeps.
- [`experiments/quantization/plot_llama_loss_comparison.py`](experiments/quantization/plot_llama_loss_comparison.py)
  and [`experiments/quantization/plot_resnet50_loss_comparison.py`](experiments/quantization/plot_resnet50_loss_comparison.py)
  generate loss-comparison figures.
- [`experiments/yolov8/plot_yolov8n_accuracy_comparison.py`](experiments/yolov8/plot_yolov8n_accuracy_comparison.py)
  and [`experiments/yolov8/plot_yolov8n_loss_comparison.py`](experiments/yolov8/plot_yolov8n_loss_comparison.py)
  generate YOLOv8 comparison plots.

## Output and Cache Directories

Several directories contain generated artifacts rather than hand-written source:

- `debug_logs/`: timing/debug logs.
- `trace/`: profiler or runtime traces.
- `tb_scalars/`: TensorBoard scalar exports and derived plots.
- `experiments/results/`: curated result CSV/PNG/SVG outputs.
- `experiments/quantization/outputs/`: quantization experiment outputs.
- `experiments/yolov8/outputs/`: YOLOv8 run outputs.
- `bitscom/build/`: extension build products.
- `__pycache__/`, `.pytest_cache/`, `.cache/`: Python/test/tool caches.

Before committing, review generated outputs intentionally; many runs produce
large or environment-specific files.
